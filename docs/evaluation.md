# Evaluation

How detection quality is measured, what the current numbers mean, and what
they explicitly do **not** prove.

## Method

The guard is evaluated against a synthetic corpus of Chinese clinical notes
generated by `tools/generate_synthetic_cn_notes.py` and stored under
`tests/fixtures/synthetic_cn_notes/`.

Every document ships with a `*.spans.json` sidecar recording sensitive types
and character offsets in the detector's coordinate space. Each document must
follow its declared lifecycle, not necessarily every pipeline stage. The normal
corpus expects **135 SANITIZE, 5 ASK, and 35 ALLOW**. The five rare-context ASK
notes carry annotations but must not produce a released payload.

### Detection metrics: historical overlap vs strict matching

The historical scorer counted a same-type overlap as a hit. A one-character
match within a longer name could therefore receive full recall credit. The
historical 1.0 scores below do not establish complete-span detection.

The hardened scoring contract requires **one-to-one matching on type, start,
and end offsets**. Each label and detection can match at most once. Partial,
over-wide, wrong-type and duplicate detections cannot count as complete hits;
unmatched labels are false negatives and unmatched span-level detections are
false positives, including types not declared by that document. Strict recall
is `TP / (TP + FN)` and strict precision is `TP / (TP + FP)`. Neither is a
false-positive rate over all possible negative spans. Overlap metrics, if
retained for comparison, must be labelled separately from strict metrics.

False positives are measurable on **both** annotated and identifier-free
notes. `false_positives_on_clean_documents` isolates the latter; it does not
replace the overall false-positive count. Exact detection also does not prove
that the transformer processed every target: that needs independent execution
evidence and policy-specific postconditions.

### Per-document lifecycle and audit gates

The remediation contract requires the following checks for each document:

| Expected verdict | Required outcome |
|---|---|
| SANITIZE | Complete planned transformations, successful verification, a released sanitized payload, and a valid corresponding audit event |
| ALLOW | An unchanged released payload and a valid corresponding audit event; no transformation is required |
| ASK / BLOCK | No released payload and a valid audit event for that outcome |

Separate lifecycle counts must distinguish unchanged ALLOW releases, verified
SANITIZE releases, ASK, BLOCK and failed verification. An initial SANITIZE
decision is not successful sanitization; a final BLOCK caused by verification
failure must fail the expected-SANITIZE check. For this corpus, 135 successful
verifications and 170 releases are expected, but aggregate counts alone cannot
substitute for per-document checks.

The hardened gates must reject:

- any document whose initial decision, verification or final release differs
  from its declared lifecycle, including a single missing SANITIZE release;
- any `verification_failure_count`, pipeline error or missing required
  verification, even if all 35 ALLOW notes still release;
- missing, extra, unreadable, malformed or mismatched audit records. Audit
  existence, count, structure, request association and decision/verification
  consistency are independent requirements; an empty log is not a clean log;
- false ALLOW decisions, residual labelled sensitive values or audit raw-value
  leaks, subject to the documented transformation/context exceptions;
- strict detection false negatives and false positives, with per-type results
  as well as aggregate results.

Residual string searches alone are insufficient: deleting one character from
a name can evade a search for the whole original value. Full target-span
handling must be checked against transformation evidence, not input offsets
applied directly to output whose length has changed. Generalization must meet
its type-specific precision requirement; DATE_SHIFT must match the expected
shift and preserve intervals, rather than merely differ from an original date.
Audit scans exclude timestamp metadata that can coincide with labelled dates;
internal transformation evidence and token maps must never enter that log.

Any failed benchmark gate must make the CLI exit `2`. Fault-injection
acceptance includes all/single verification failures, absent/partial/corrupt
audit logs and partial-span detection. Latency (p50/p95) is informational, not
a gate. These are the hardened acceptance requirements, **not a claim that a
new run or fault-injection suite has passed**. Exact JSON field names and the
post-remediation results are recorded in "Remediated strict results" below.

### Policy context

The baseline uses `external-ai-strict/1`, recipient `EXTERNAL_APPROVED`, and
purpose `EXTERNAL_AI_ASSISTANCE`. This represents an endpoint approved by the
deploying organization, not approval inferred or authenticated by the library.
Most annotated notes should be sanitized; rare-context notes still ASK.

Using `--recipient external_unknown` changes policy outcomes and is expected
to fail agreement with this corpus's approved-recipient expectations. Detection
scores can still be computed on inputs even when nothing is transformed;
zero residuals with no released payload are not proof of successful sanitization.

Run it with:

```bash
medical-privacy-guard benchmark tests/fixtures/synthetic_cn_notes
medical-privacy-guard benchmark tests/fixtures/synthetic_cn_notes --json
```

### Identifier-free notes

The 35 identifier-free documents isolate over-redaction on **near-miss** phrases
without legitimate identifier spans. Annotated notes can also expose overreach:
a detection outside a label or with the wrong type/boundary is not explained
away by another valid identifier in that document.

| Near miss | Looks like | Actually is |
|---|---|---|
| `本病区`, `各病区`, `该病区` | a ward designation | a generic reference to a ward |
| `男病房`, `男女比例`, `男性与女性受试者` | a patient's sex | a room, a statistic, a study cohort |
| `共12名医生`, `主任医师`, `责任护士` | a staff name | a headcount and job titles |
| `床位紧张` | a bed number | a capacity concept |
| `三级甲等医院`, `上级医院`, `当地医院` | an institution name | a grade and generic references |
| `50岁以上人群`, `纳入18岁以上成人` | a patient's age | a population threshold |
| `加强罕见病诊疗管理` | a re-identification claim | health-policy language |
| `剂量120000单位`, `住院6天` | a postal code, an age | a dose and a length of stay |

After the hardening work, the same 175-document corpus was rerun with the strict

| `false_positives_on_clean_documents` | 0 |
| `false_negatives` | 0 |
| `verdict_mismatch_count` | 0 |

| `audit_raw_leak_count` | 0 |

| `lifecycle_failure_count` | 0 |

Result: **PASS**. This is a stricter bar than the historical run: the same 1.0
now means every label is matched by a detection of the same type with identical
start and end offsets, and every document follows its declared lifecycle.

Fault injection confirms the gates reject rather than merely observe: forcing
all 135 verifications to fail yields `passed=False` with `verification_failure`,
`lifecycle_failure` and `sanitize_path_not_exercised`, while disabling audit
writes yields `passed=False` with `audit_failure` and `audit_missing_count=175`.

The strict scorer immediately found a real defect the overlap scorer had hidden:
in `consultation_note_020`, the labelled rare-context phrase `罕见变异型病例`
was detected only as `罕见变异`, and the diagnostic `MEDICAL_CONTENT` match on
`疾病` then outranked and discarded the shorter rare-context fact during merge.
A one-character-overlap hit had accepted this before. Both were fixed — the
rare-context pattern now covers the full phrase and document-level
classifications no longer displace span-level facts — so the ASK path is not
silently skipped for a patient-attributed rare disease.

## Test and packaging status

Verified on 2026-09-19: 619 tests pass on Python 3.10, 3.11 and 3.12; `ruff`
and `bandit` are clean; `pip-audit` reports no known vulnerabilities in the
dependency set; `python -m build` produces an sdist and wheel; and the installed
wheel passes both the `Guard.sanitize` smoke test and the `medical-privacy-guard`
console entry point from outside the source tree. The benchmark CLI exits `2`
on a failed gate.

Passing these checks means the regressions above are pinned, not that detection
generalises. The corpus remains template-generated and the recall of 1.0 is
still a measure of internal consistency; fault injection proves the gates can
fail, not that every real-world failure mode is enumerated.

### What the negative corpus found

The negative half is not decoration: on its first run it exposed five real
defects, all of which had passed the existing unit tests.

- **`WARD` matched `本病区`** — at the start of a line the preceding-character
  guard cannot help, so the generic phrase "this ward" was captured as a ward
  designation. Generic prefixes are now rejected.
- **`HOSPITAL_NAME` matched `该院为三级甲等医院`** — the whole sentence was
  reported as an institution name. Generic qualifiers (`上级医院`, `当地医院`,
  `三级甲等`) are now rejected, and a match containing a function word is
  discarded as a swallowed phrase.
- **`AGE` matched `50岁以上人群`** — a population threshold was treated as a
  patient's age. Ages are now attributed to the patient only.
- **`RARE_CONTEXT` matched `加强罕见病诊疗管理`** — health-policy language was
  treated as a re-identification claim. The rare-disease branch now requires a
  case reference (`本例`, `该患者`, …).
- **`DEPARTMENT` matched `建议神经内科会诊`** — a referral target was treated as
  the patient's own department. Department names now require a field label, a
  patient-movement verb, or a following location noun.

Each fix is pinned by a unit test carrying the exact phrase, so the same
regression cannot return silently. The corpus also surfaced a reproducibility
bug: a department pool was built with `tuple(frozenset)`, whose order follows
`PYTHONHASHSEED`, so the "byte-exact reproducibility" claim held only on the
machine that generated the corpus. A subprocess test now runs the generator
under two hash seeds and compares digests.

### What the benchmark itself was hiding

Earlier work corrected context-only verification handling and prevented age
bands and transformer markers from being re-detected as fresh identifiers.
Those repairs were necessary, but aggregate release counts and a non-vacuity
check did not establish that failures would be rejected.

The 2026-09-19 audit reproduced three distinct false assurances:

- Injecting failure into all 135 verifications still produced PASS because 35
  unchanged ALLOW notes released, and verdict comparison used the pre-transform
  decision. Verification failures do not necessarily mean zero verifications.
- Suppressing all audit writes still produced PASS and zero raw audit leaks:
  the absence of a record was not being checked independently.
- A same-type one-character detection could receive full credit for a longer
  labelled name. Searching only for the full original value could also miss a
  partially deleted identifier.

The per-document lifecycle, audit-integrity and strict one-to-one requirements
above address these separate gaps. A normal successful run alone does not show
that failure gates work; fault injection must demonstrate rejection. Nor should
ASK notes be forced through transformation to inflate release coverage.

### Non-transformable context types

`SEX`, `MEDICAL_CONTENT` and `RARE_CONTEXT` are context signals that policy does
not require the text transformer to replace. A fact may have a span and still
be context-only. Approved-recipient policy may retain sex and clinical content;
rare-context notes in this corpus return ASK with no released payload. These
exceptions do not permit skipped transformations of other types, particularly
untransformed exact dates.

## What these numbers do not prove

**The corpus is generated to match detector capabilities.** Historical overlap
recall of 1.0 measures agreement with known templates, not generalisation,
complete-span handling or the absence of all residual PHI. Even a strict score
of 1.0 on this corpus would not estimate performance on real clinical text.

Important limitations include:

- **Names depend on markers and a surname inventory.** Labelled/adjacent patient
  names and title/suffix staff names are supported; arbitrary narrative names
  and uncommon surnames remain outside the documented baseline.
- **Institution vocabulary is bounded.** Built-in department names do not cover
  every hospital's local unit names or abbreviations.
- **Record identifiers depend on known labels.** Specimen/accession/bed numbers
  in unfamiliar narrative contexts may be missed.
- **Format variation is not exhausted by the normal corpus.** Current phone
  detection supports contiguous or 3-4-4 grouped mobile numbers with ASCII or
  full-width digits. Date detection accepts real calendar dates in 1900–2099,
  including YMD and MDY forms with non-zero-padded months/days, and preserves
  original character spans. This does not imply arbitrary Unicode, OCR-noise
  or date-format coverage; new challenge results must be reported separately.
- **Quasi-identifier combination risk is not measured.** Document-level rule
  signals are not dataset-level re-identification analysis.

**Precision is a proportion, not a lower bound on false positives.** Under
strict matching it is `TP / (TP + FP)`. It is distinct from a false-positive
rate `FP / (FP + TN)`; this span benchmark does not enumerate all possible true
negative spans. Zero observed false positives applies only to the annotated
and identifier-free examples scored, not unseen clinical prose.

**The verdict gate checks stated expectations, not institutional approval.**
SANITIZE/ASK/ALLOW labels encode a small set of declared policy expectations;
correct agreement does not establish legal consent or the institution's desired
policy. No facts is not proof of safety, and shared detector blind spots can
survive both initial detection and verification.

## Verification requirements

1. **Transformer markers are inert.** Re-detecting markers or age bands as fresh
   identifiers can block otherwise valid releases; the policy re-run must not
   demand endless transformations of already generalized values.
2. **Execution evidence is checked independently.** Matching action labels or
   a changed output string is insufficient. Every target needs complete
   processing and its policy-specific postcondition. No-op GENERALIZE and
   DATE_SHIFT must fail; shifts must match the expected nonzero offset and
   preserve date intervals, including when an output date coincides with a
   different input date.
3. **Success and rejection are both evaluated.** Retaining approved context
   signals must not become a blanket exemption for incomplete operations.
   Audit short writes and output/input/audit collisions must withhold release.

## Adding detectors

Extend regression templates and their annotations alongside positive and
negative detector tests; include near misses in both annotated and clean notes.
Maintain an independent synthetic challenge set rather than only generating
values tailored to the new regex. Cover grouped/full-width numbers, date
variants, narrative names, institution abbreviations and OCR noise according
to the actual implemented scope. Any normalization must preserve original-span
mapping so the full source value is transformed.

Compare strict per-type recall and precision, inspect unmatched spans, and run
all lifecycle and audit gates. Do not treat equal labelled/detected counts as
proof of exact matching, accept all-BLOCK as safety success, or weaken ASK policy
to improve release totals. Historical overlap scores must remain clearly labelled
when compared with new strict results.
